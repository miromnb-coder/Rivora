# Phase 7.5 — Copilot privacy and customer readiness

**Review required, not legal approval.** All client-facing statements must reflect verified runtime behavior and current agreements.

## Data flow
1. The signed-in user types a question and optional recent conversation history. The browser only includes selected workspace ID and active record hint when the user has opted into workspace data.
2. Server validates origin, session, membership, selected organization, private pilot / audience gate, RLS, rate limits and feature flags.
3. Bounded read-only RFC/RFQ/Orders and Phase 6 Product Memory evidence is fetched using the authenticated tenant-scoped DB client. Source records and user content are *untrusted* data.
4. Only sanitized, size-limited context is sent to OpenAI after a conservative cost reservation. No password, API key or customer raw database dump should be sent. The OpenAI request sets `store:false`; review vendor contractual retention and processing arrangements independently.
5. Model deltas stream to the browser. Source/findings/evidence metadata is displayed only after successful AI completion and ledger settlement. The server never treats the model as evidence-authority.
6. Existing technical ledger writes remain stored in Supabase, including ambiguous usage reservations. New Phase 7 lifecycle logging records only whitelisted classification data and request IDs; no prompts, RFQ text, user/customer IDs, source UUIDs or provider error messages are added.
7. Existing privacy page states only broad retention principles. Record actual retention periods for conversation state, server logs, billing records, request identifiers, backups, and support data before customer beta.
