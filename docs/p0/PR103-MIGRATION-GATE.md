# PR #103:n rajatun tuotantokorjauksen portti

Tämä valmistelu kuuluu P0-diagnostiikan luonnos-PR:ään #104. Se ei muuta PR #103:n alkuperäistä migraatiota `20261010140726_catalogue_integrity_guided_import.sql` (SHA-256 `cefda4ec9a94efd6743986068942e1010acb0cc817a573157fceb2de5fab3d38`). Phase 2A:n kuusi uutta migraatiota ja tuotantokytkimet käsitellään erillään PR:ssä #105.

`P0-PR103-READONLY-GATE.sql` palauttaa yhdeksän riippuvuuden kyllä/ei-tilan, SKU-konfliktien määrät, RLS- ja RPC-oikeuksien tilan sekä migraatiohistorian olemassaolon. Se ei tulosta SKU-tunnisteita, asiakastietoja eikä organisaatiotunnuksia. Suoritus kuuluu vasta siihen tuotantoprojektiin, jonka aktiivinen palvelinpuolen yhteys on todistettu. Historiaversion tarkistus on erillinen SELECT, jotta puuttuva schema_migrations-taulu ei estä muiden tarkistusten tulosta.

Ennen tuotannon SQL-kirjoitusta tarvitaan: 1) kyseisen aktiivisen deploymentin serveripuolen todellinen Supabase-projektitunniste ja muuttumaton konfiguraation todiste; 2) salattu ja hyväksytyssä tallennuspaikassa oleva ajantasainen DB/Auth/roolit/oikeudet/migraatiohistoria + Storage-objektit/metatiedot + Vault-avainriippuvuudet + sovellusasetukset; 3) onnistunut palautus eristettyyn ympäristöön; 4) nykyistä tuotantoschemaa vastaava staging sekä PR #103:n migraation, regressioiden, replayn, RLS:n ja selaimen integraation testit; 5) erillinen tuotantokorjauksen hyväksyntä. Ilmaisella Supabase Free -tasolla ei ole osoitettua automaattista palautettavaa backupia/PITR:ää. CI:n synteettinen pg_dump/restore ei korvaa oikeaa palautuskokeilua. SKU-konflikteja ei yhdistetä tai muuteta automaattisesti.

Rajattu toteutus hyväksynnän jälkeen: lukitse muutosikkuna, varmista tuore backup ja stagingnäyttö, suorita vain PR #103:n migraatio oikeassa projektissa, mittaa kaikki yhdeksän kohdetta ja oikeudet uudestaan, testaa synteettinen katalogiesikatselu/commit luvallisessa tuotantokokeessa ja vertaa tuotantodeploymentin schema-yhteensopivuus. Peruutus palautuksesta hyväksytyn harjoituksen mukaisesti; alkuperäisiä ID:itä, tuotevastineita, kaupallisia snapshotteja tai auditointia ei rekonstruoida arvaamalla. Jos jokin portti puuttuu, tila pysyy P0 BLOCKED eikä migraatiota ajeta.
